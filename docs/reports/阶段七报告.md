```

```

**结构自洽性断言（离线可查的）**：PD120 每个行对 `0.020 + 0.00208 + 4×0.1216 = 0.50848 s` × 248 对 = **127.11 s**（实测编码时长一致）；PD180 `scanTime` 恰为 PD120 的 **1.5000 倍**（同步脉冲与 blanking 两者共享，所以行对时间之比是 1.4783 而非 1.5——我最初的断言写错了，已修正并写进注释）；R−Y 与 B−Y 系数**各自和为零**（否则灰色会带色偏）；PD120 与 PD180 除 `scanTime`/`vis` 外**所有字段相同**，因此共用一条代码路径。

### 2.1 三个真实 bug（全部靠测量定位，不是靠猜）

**① 窗因子太短：PD120 的像素时间只有 190 µs**

`windowFactor` 原来是 `null`（阶段一"PD 解码不在范围内"），我最初填 2.34（照抄 M1）。**结果是 21 个采样的窗口，不足 1200 Hz 的一个周期（40 采样）**，窗内不足一周期时 Hann 窗主瓣宽达 9 kHz，峰位随相位漂移，频率估计完全失真。

窗因子扫描（解析精确起点，排除对齐干扰）：

| windowFactor | 窗口采样 | @1200Hz 周期数 | 水平模糊 | PSNR | Y 平面 RMS 误差 |
|---|---|---|---|---|---|
| 2.34 | 21 | **0.53** | 2.3 px | **5.93 dB** | 119.5 |
| 4 | 36 | 0.90 | 3.9 px | 20.97 | 13.1 |
| 6 | 55 | 1.38 | 6.0 px | 25.07 | 8.9 |
| **8** | 73 | **1.82** | 8.0 px | **26.42** | 8.0 |
| 16 | 146 | 3.65 | 16 px | 26.73 | 7.9 |
| 32 | 292 | 7.30 | 32 px | 26.59 | 7.6 |

**取 8**（平台起点、模糊最小）。判据是"窗内至少 ≳1.8 个最低音周期"。

**② VIS 停止位与第一个同步脉冲都是 1200 Hz 且相邻**

PD 的 VIS 头以 1200 Hz 停止位结束，**紧接着**就是 1200 Hz 的同步脉冲，两者**没有间隔**。未钳制的向后搜索会锁到停止位上，使全部块整体偏移。修法：搜索下界钳到 `imageStart`（块 0 直接用 `imageStart`，它由 VIS 头精确给出，实测 delta=0）。

**③ "最小频率"无法定位 20 ms 同步脉冲（最隐蔽）**

20 ms 的分析窗**恰好和脉冲一样长**，所以估计值在脉冲内外好几个 ms 都是 **1195.5 Hz 的浅平台**——搜索于是返回"它自己窗口的起点"，**每个块提前 288 采样（6 ms ≈ 32 像素）**，正好等于粗搜半径。

改用**下降沿检测**：3 ms 短窗寻找频率跨越 ~1350 Hz 的位置，再按几何关系补偿半窗。中途还踩了两个子坑，都记在代码注释里：
- **扫描方向错了**：`bestOff` 落在真实起点**之前**，所以"从 bestOff 往回扫"永远扫不到沿（实测：33 个候选全部未命中）。必须**向前扫**。
- **系统性偏置**：跨越点估计比真实沿**超前约 24 采样（0.5 ms）**，需减去该偏置。

**修正前后的影响**：块锁定误差从 **−288 采样降到 +23 采样**，PSNR 从 **24.35 → 32.46 dB（+8.1 dB）**。

**PD120 的能力边界（必须点明）**：像素时间 190 µs ⇒ 调制率约 **5.3 kpx/s** ⇒ PD120 音频**需要 ≥16 kHz 采样**。8 kHz 录音对 PD120 **低于 Nyquist**，这不是实现缺陷而是体制事实（这也解释了为什么 PD 录音通常以 22.05 kHz 以上存档）。

### 2.2 PD 自洽验证的局限（如实说明）

**外网被重度过滤，我拿不到 PD120 规格文档**（archive.org/wikimedia 超时，sigidwiki 两侧 403），**也搜不到任何真实 PD 模式录音**（试了 6 个 GitHub 仓库，只找到 M1 的样本）。

所以**上述往返只证明"我的解码器能解我的编码器"**。可离线核对的结构事实我已逐项断言（行对时序、总时长、系数和为零、两模式共享路径），但**逐像素时序的绝对正确性未经外部验证**。这条必须带着走。

## 3. findHeader 修改前后的对比（AC4 ✅ / AC5 ❌）

### 3.1 改动内容（按你确认的"主路径不变 + 失败才回退"）

阈值从写死的常数改为可参数化：
```js
primary : { wide:200, pairTol:30,  breakTol:60,  sepLo:0.88, sepHi:1.12 }
fallback: { wide:700, pairTol:120, breakTol:260, sepLo:0.70, sepHi:1.30 }
```
`decode()` 先用 primary；**只有返回 null 才用 fallback**。放宽阈值必然抬高误检率，所以回退结果**不被单独信任**：下游还要解出 **VIS 偶校验正确且映射到受支持模式**，否则仍报错。

### 3.2 实测对比

| | 主路径 | 回退路径 | 结果 |
|---|---|---|---|
| clean M1（`real-npm-8k`） | 命中，header **157 ms** | 从不触发 | **零额外成本** ✓ |
| `ssb-agc` / `awgn-12` | 命中（`source=primary`） | 从不触发 | 零额外成本 ✓ |
| `ssb-hum` | 未命中 | **未命中** | **仍失败**，两轮全扫 **6067 ms** |
| `ssb-adjacent` | 未命中 | **未命中** | **仍失败** |
| `acoustic-band` | 未命中 | **未命中** | **仍失败** |

**AC4（检测时间 ≤ 原 2 倍）**：**对成功的文件是 1×（回退不触发）✓**；对失败的文件是两轮全量扫描，**用户会多等约 6 s 才看到报错**——如实记录，这是可接受的代价但仍是一个 UX 退化。

### 3.3 **假说被证伪（本轮最重要的负结果）**

我在方案里提出的假说是："失败源于**固定阈值裕度被两个损伤叠加耗尽**，改成噪声底归一化 + 放宽阈值即可救回"。

**实测把这个假说否定了**：把接受阈值放宽 **3.5 倍**（`wide` 200→700、`pairTol` 30→120、`breakTol` 60→260、`sep` ±12%→±30%），**3 例失败一例都没救回**，全部仍然 `hdr=none`。

这说明失败**不是"差一点过阈"**，而是**检测器在整个文件里找不到任何候选**——即"引导音—间隔—引导音"这个**模式本身被破坏了**，而不是判定门限偏紧。

**因此正确的下一步方向也随之改变**（见 §8）：不是继续调阈值，而是要么恢复/重建引导音模式（例如对带外能量做自适应白化、或改用不依赖 300 ms 引导音的同步音周期检测），要么换一个与引导音模式无关的起点估计方法。

## 7. 对"下一步该做什么"的建议（报告第 8 项）

按实测收益与确定性排序：

1. **换掉"最小频率"式的起点估计**（最高优先）。AC5 的失败已经证明**调阈值无效**，根因是引导音模式被破坏。可行方向，按代价从小到大：
   - **对带外能量自适应白化**后再做引导音检测（工频与邻道正是带外能量，这条直接对症）；
   - **不依赖 300 ms 引导音的"同步音周期检测"**：用逐行同步音的周期性做周期图，直接给出起点与行时，再回推 VIS 位置；
   - **多假设搜索**：允许引导音频率有较大偏移（`wide` 需到 ±700 Hz 以上并配合归一化得分），但**必须配 VIS 偶校验 + 连续 N 个同步一致**做验证，否则误检率会失控。
2. **给 PD 族做真实音频验证**。目前 PD120/PD180 只有自洽往返；**规格文档与真实 PD 录音都取不到**，这是最大的不确定性。若将来网络可用，优先取一段 ARISS PD120 录音。
3. **PD 解码降本**。当前 PD120 解码约 **46 s**（M1 约 7 s），主要花在 634,880 次逐像素 FFT 上。可行的加速：块起点一次线性拟合后不再逐块搜索、用更小的 FFT 上限、或对像素窗做多相分解。
4. **PD 的时频权衡可以做得更好**：当前用 8 倍窗（8 px 模糊）换取频率分辨率。**相位差/瞬时频率类估计器**能在同样窗长下显著提高频率精度，从而减模糊、提 PSNR。这是把 PD 从"能解"推到"解得好"的关键。
5. **（按你本轮明确排除，仅记录）** SSB 频响校正、后处理改进、AFC 优化、更多真实样本采集。
