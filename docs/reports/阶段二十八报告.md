### 1.2 架构：检测在 `Demodulator`，**决策在 `Decoder`**

- `Demodulator.process(...)` 逐样本返回 `syncPulseDetected / syncPulseWidth / syncPulseOffset / frequencyOffset`
- **`Decoder` 才是"是否接受这个同步"的裁决者** —— 关键逻辑在 `Decoder.processSyncPulse()` ✓

### 1.3 检测层（`Demodulator`，经 TS 移植版核对）

| 步骤 | 做法 |
|---|---|
| 复基带 | 中心 **1900 Hz** = (1000+2800)/2；复低通 **2 ms 长度、900 Hz 截止** |
| FM 解调 | 偏差由 `scanLineBandwidth = 白−黑 = 800 Hz` 定，故 **归一化值 = (f − 1900)/400**<br>→ `norm(1200) = −1.75`、`norm(1500) = −1.0` |
| 平滑 | **2.5 ms 滑动平均**（5ms/2，强制奇数）+ 配套 `Delay` 对齐 |
| **Schmitt 触发** | 阈值取**中点**：`(1200+1500)/2 = 1350 Hz → −1.375`、`(1200+1350)/2 = 1275 Hz → −1.5625`<br>1200 Hz 同步把值拉过 −1.5625 → 触发；升过 −1.375 → 释放 |
| 脉宽 | **下降沿**计 latch 长度 |
| 校验 | 宽度 ∈ **[2.5, 25] ms**（= 5ms/2 … 20ms+5ms）**且** `|延迟值 − norm(1200)| ≤ (50×2)/800 = 0.125`<br>**这条就是 ±50 Hz 的实现** |
| 分档（**中点**） | `< 7 ms` → 5ms；**`< 14.5 ms` → 9ms（Scottie S1 所在档）**；else 20ms |
| 输出 | 脉冲**结束位置**（延迟补偿）+ **频偏**（供 AFC） |

**与任务书的两处出入（都用实测说明）**：

| 任务书要求 | 实际 | 依据 |
|---|---|---|
| 脉宽只接受 **8~10 ms** | 上游是 **[7, 14.5) ms** 归入 9ms 档，有效区 [2.5, 25] ms | 阶段二十六实测真实录音脉宽中位 **7.75 ms** → **8~10 ms 会把多数真脉冲拒掉** ✗ |
| 需要**自适应噪声底** | **没有**噪声底估计 | 抗噪来自 **Schmitt 迟滞 + 脉宽门 + ±50 Hz 门 + （关键的）§1.4 的逐脉冲裁决** |

### 1.4 决策层（`Decoder.processSyncPulse`）——**真正的鲁棒性来源，我最初的总结漏了它**

```java
syncIndexes[last] = latestSyncIndex;                            // 5 格移位寄存器
lineLengths[last] = syncIndexes[last] - syncIndexes[last-1];    // 最新间隔
freqOffs[last]    = demodulator.frequencyOffset;

double mean = scanLineMean(lineLengths);                        // 【最近 4 个】间隔的均值
int scanLineSamples = (int) Math.round(mean);
if (scanLineSamples < scanLineMinSamples || > scratchBuffer.length) return false;
if (scanLineStdDev(lineLengths, mean) > scanLineToleranceSamples) return false;   // ★ 1 ms 门限
...
if (currentMode != rawMode &&
    Math.abs(scanLineSamples - currentMode.getScanLineSamples()) > scanLineToleranceSamples)
    return false;                                                // ★ 必须与该模式标称行长相符
...
float frequencyOffset = frequencyOffsetMean(freqOffs);           // ★ AFC = 最近 ≤5 个脉冲的频偏均值
```

**四个要素**（`scanLineToleranceSamples = 0.001 s = 48 采样`）：

| # | 机制 | 作用 |
|---|---|---|
| 1 | 行周期 = **最近 4 个间隔的均值**（不是全局拟合） | 只反映当前时钟 |
| 2 | **标准差 > 1 ms → 整次更新作废**，沿用上一值 | **污染被"拒绝"而不是被"平均"** ✓✓ |
| 3 | 每个同步还须与**模式标称行长**差 ≤ 1 ms | 逐脉冲强门限 |
| 4 | `currentSample > lastSyncPulseIndex + 1.25 × 行周期` → 按旧速率**自由运行**解一行 | 失锁不致命 |

**这就是为什么我们三种全局估计全都会失败**：全局拟合让污染**累积**；
它是**逐脉冲门限**，污染**被拒绝** ✓
**且阶段二十六实测该录音的间隔 MAD = 0.4389 ms → 能通过 1 ms 这道门** ✓✓

**5ms/9ms/20ms 三类模式各自维护自己的历史数组**（`last9ms*` 对应 Scottie S1/2/DX、Robot36/72）✓
模式由 **VIS 码**确定：`syncPulse9msModes` 中 `RGBModes.Scottie("1", 60, 0.138240, ...)` 即我们的 S1 ✓

## 6. 任务 3.5（AFC / 时钟恢复 / findHeader）—— **未做**，但拿到了规格

**未做** ❌（预算）。不过 Java 源码已经把三条依赖关系讲清楚，可直接作为下一轮的检查清单：

| 项 | Java 的做法 | 对我们的含义 |
|---|---|---|
| **AFC** | `frequencyOffsetMean(freqOffs)` = **最近 ≤5 个脉冲的频偏均值**，传入 `decodeScanLine(...)` | 是**短窗滑动 AFC**，不是全局仿射标定 ✗ 我们的 `calib.a/b` 是全局的 → **替换检测器会牵动 AFC 口径** |
| **时钟恢复** | 即 §1.4 的**最近 4 间隔均值 + 1 ms 门限**，替代"全局行斜率拟合" | 我们的 `measuredLineSamples` 是全局 LS ✗ → **这才是本轮真正该改的地方** |
| **findHeader 回退** | `handleHeader()` 独立搜 VIS；**无同步时**由 `currentSample > lastSyncPulseIndex + 1.25×行周期` 触发**自由运行**解行 | 我们有 `findHeader` 与逐行 `alignSync` 搜索，**但缺"1.25 行自由运行"这一级** ✗ 替换检测器时**必须同时提供该回退**，否则失锁即彻底中断 |

**结论**：**替换检测器不是独立的改动** —— 它绑定 AFC 口径与失锁回退 ✓
这正是任务 3.5 想防的风险，**我的答案是：有依赖，且依赖比预想更深** ✓

## 7. 本轮结论与下一轮建议

**核心结论**：**Robot36 的鲁棒性主要不在它的检测层，而在 `Decoder` 的逐脉冲裁决层** ✓
检测层（Schmitt + 脉宽 + ±50 Hz）我们已经能做得不差（既有包络检测器实测 MAD 0.44 ms）；
**真正缺的是那四件事**：最近 4 间隔均值、**1 ms 标准差门（污染拒绝而非平均）**、
**与模式标称行长相符**、**1.25 行自由运行回退** ✓

**下一轮建议（按优先级）**：

| # | 动作 | 理由 |
|---|---|---|
| **1** | 修 §2.3 的解调标度（打印已知脉冲处的 `fm`/`sv` 局部均值，一次分流） | 新检测器自检必须先过，否则一切集成都是空的 |
| **2** | 在**不改检测器**的前提下，先把 `measuredLineSamples` 的更新改成 **"最近 4 间隔均值 + 1 ms 标准差门 + 与标称行长比对"** | **这是 Java 的鲁棒性核心**，且**与替换检测器解耦**，可单独验证 ✓ |
| **3** | 加 **1.25 行自由运行回退** | 失锁时保持产出；也直接对应"顶部有结构、其后噪声"的症状 |
| **4** | 检测器替换放在最后，并**同时**核对 AFC 口径 | 按 §6 的依赖关系 |

**预期的判据**：阶段二十六已实测该录音间隔 MAD = **0.4389 ms < 1 ms** →
**能通过 Java 那道标准差门** ✓ 所以第 2 项**有明确的数据支持**，这是本轮最有价值的可执行结论 ✓
