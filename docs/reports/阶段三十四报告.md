## 2. ★ 根本性发现：信号频率被整体搬移（报告第 2 项）

### 2.1 证据

```
[任务 2] 各槽中位频率（全帧统计）
  G 槽: 中位 1044.9 Hz (MAD 26.0, 极值 647..1658)
  B 槽: 中位 1045.0 Hz (MAD 28.2, 极值 702..1567)
  R 槽: 中位 1066.2 Hz (MAD 25.1, 极值 719..1567)

[AC6] 中位频率分布
  区间(Hz)      G 行数   B 行数   R 行数
  0-1250         254     254     255      ← 几乎所有行
  1250-1350        0       0       0
  1450-1550        0       0       0      ← 分隔音 1500 Hz 上【没有】任何行
```

### 2.2 读数

| 观测 | 含义 |
|---|---|
| **三个槽的中位频率几乎相同**（1044.9 / 1045.0 / 1066.2）✗ | 这正是"三通道内容雷同 → 发灰"的机械原因 ✓ |
| **全部低于同步音标称 1200 Hz** ✗ | 同步音**实测在 ~1045 Hz** ✓ |
| **比值 1045 / 1200 = 0.871（−12.9%）** ✗ | **频率轴被搬移** ✓ |
| **时间轴正常**（间隔中位 427.750 ms = 标称 428.22 的 99.89%）✓ | **不是变速** ✗ —— 否则时间轴也会被同比拉伸（应变成 492 ms）✗ |
| **1500 Hz 区间 0 行** ✗ | 分隔音也不在标称位置上 ✓ |

**⇒ 时间对、频率不对。** 这不是"播放速度变了"（那会同时改变时间轴）✗
而是**频率轴被单独搬移** ✓（仿射：`f' = a·f + b`，其中 a ≈ 0.871 量级）

### 2.3 为什么解码器还能解出图形

**解码器的标定正是干这个的**：
```
calF(f) = (f − calB) / calA          // 把【实测频率】映射回【标称频率】
```
标定由**标定头**（1900 Hz 前导、1100/1300 Hz VIS 比特）拟合而来 ✓
→ **它把 0.871 的搬移吸收进 `calA`** ✓ → 之后所有 `calcLum(...)` 都在**标称轴上** ✓
→ **所以解码器解出的图是有意义的** ✓ 而你截图里能看到轮廓，正是因为标定在工作 ✓

### 2.4 ⚠️ 我的诊断脚本从未应用这个标定 —— 这是三轮测量的共同缺陷

我的脚本一律用：

```js
const greyOf = (hz) => clamp(255 * (hz - 1500) / 800);     // 标称轴
const probe  = ...                                          // 但读的是【原始】频率
```

**原始频率 ≈ 1045 Hz** → `greyOf(1045) = clamp(255 × (1045−1500)/800) = 0` ✗✗
→ **三个色平面被整体钳成 0** ✗ → 色差 ≈ 0 → **"源色度无结构"是纯伪影** ✗

**受影响的结论（全部撤回）**：

| 轮次 | 撤回的结论 |
|---|---|
| **阶段三十** | "源头饱和度 32.7 = 参照的 76% → 源头有色" ✗ 那是钳位后的残差 |
| **阶段三十** | "四项假设都洗清" ✗ 网格本身建立在错误的灰度映射上 |
| **阶段三十二** | "B/R 槽采在没有音调的地方" ✗ 是"**所有槽都在未标定的低频处**" ✓ |
