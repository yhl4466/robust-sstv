## 2. 格式探测的实现（报告第 2 项）

读**前 12 字节**判定容器（`js/lib/audio-input.js` 的 `detectFormat`）：

| 判据 | 判定 | 实测样本的魔数 |
|---|---|---|
| `RIFF` + 偏移 8 = `WAVE` | **WAV** | `52 49 46 46 … 57 41 56 45` |
| 偏移 4 = `ftyp`，按 brand 取名 | **M4A / MP4 / MOV / 3GP** | `00 00 00 1c 66 74 79 70 4d 34 41 20`（`ftypM4A `）<br>`00 00 00 1c 66 74 79 70 69 73 6f 6d`（`ftypisom`） |
| `OggS` | **OGG** | `4f 67 67 53 00 02 …` |
| `ID3`，或 `FF Ex`（且排除 `FF F8` 填充） | **MP3** | `49 44 33 04 00 …` |
| `1A 45 DF A3` | **WebM** | `1a 45 df a3 9f 42 …` |
| `fLaC` / `wvpk` / `FORM`+`AIFF` / `caff` | FLAC / WavPack / AIFF / CAF | — |
| 其他 | **未知** | 报错（见 §4） |

**两条刻意的设计决定**：

1. **不是 RIFF/WAVE 就一律交给浏览器**，即使魔数不在表里。浏览器认识的容器比一张魔数表多；
   表的作用只是**给用户一个可读的名字**（"检测到 M4A"），不是充当准入闸门。
2. **探测必须发生在解码之前**：`decodeAudioData` 会 **detach** 传给它的 ArrayBuffer。这个坑实际咬了我
   一次，见 §7.3。

## 3. decodeAudioData 的接入方式（报告第 3 项）

```
选择文件 → Decoder.parseAudio(file)
   ├─ file.size > 100 MB ────────────→ 拒绝（不进 decodeAudioData）
   ├─ FileReader.readAsArrayBuffer    （不变；file:// 下可用的读文件方式）
   ├─ detectFormat(前 12 字节) + 快照十六进制预览
   ├─ WAV ──→ Wav.parse(buf)                    ← 原路径，一行未改
   └─ 其他 → AudioInput.decodeToSamples(buf)
                ├─ 取 AudioContext 单例（懒创建）
                ├─ 若 suspended：尝试 resume()，失败只产生"试听可能无声"的提示（不阻断）
                ├─ ctx.decodeAudioData(buf)     ← Promise 形式，兼容回调形式
                ├─ 多声道 → 取平均混为单声道（SSTV 是单声道信号）
                └─ 读回 audioBuffer.sampleRate / duration
   → 统一返回 { ok, samples, sampleRate, channels, bitsPerSample, format, duration, transcoded, warning }
```

**与现有流程的衔接**：解调器收到的仍是 **`Float32Array` + `sampleRate`**，接口完全相同
（`Decoder.decode(samples, sampleRate, opts)` 一行未改）→ **不改任何 SSTV 解调算法** ✓

**AudioContext 单例**：模块级 `ctxSingleton`，`getContext()` 懒创建；并提供 `contextCount()`
以便**测试断言**"确实只创建了一次"（不是靠读代码宣称）。

### 3.1 ⚠️ 对项目既有明文决定的反转（已记入注释）

`js/decoder.js` 与 `js/lib/wav.js` 原本都写着"**我们不用 `decodeAudioData`，因为它会重采样**"。
本轮必须反转它，理由已写入两处注释：

| 原决定仍然成立的部分 | 现在放宽的部分 |
|---|---|
| **WAV 仍走严格的原生采样率路径**，因为整条解调是**按秒对着文件的原生采样率**计时的 | 非 WAV 走兜底。此时重采样的落点是 **AudioContext 的采样率**（桌面约 48 kHz），而项目已实测 **8k–44.1k 全部可解**，解码器对采样率不敏感（只需高于奈奎斯特） |
| — | **实际采样率被读回并如实显示**（"48000 Hz · 已转码"），不冒充文件原始采样率 |
| — | 唯一在乎采样率的模式族是 PD120/PD180（需 ≥16 kHz），低采样率**警告但不阻止** |

## 4. 错误提示的三种情况（报告第 4 项）

实测输出（引自测试日志）：

| # | 情况 | 触发条件 | 实测提示 |
|---|---|---|---|
| ① | **无法识别的音频格式** | 魔数不认识 **且** 浏览器也解不出 | `无法识别的音频格式（前 12 字节 74 68 69 73 20 69 73 20 64 65 66 69）。支持 WAV / M4A / MP3 / OGG / WebM / MP4。` |
| ② | **音频解码失败** | 容器认得出，解码抛异常 | `音频解码失败：文件损坏，或使用了当前浏览器不支持的编码。`（由 `EncodingError` 判定） |
| ③ | **音频被截断或损坏** | 解码成功但样本长度为 0；或 WAV 头不完整 | 零字节文件：`音频被截断或损坏：文件是空的。`<br>缺数据块的 RIFF/WAVE：`音频被截断或损坏：WAV 文件不完整，缺少必要的数据块。` |
| ④（补充） | **文件过大** | `> 100 MB` | `文件过大（101 MB），浏览器音频解码上限约 100 MB，请先裁剪。` |
| ⑤（补充） | 需要页面交互 | AudioContext 无法 resume | 只作为**警告**附加（"解码不受影响，但试听可能无声"），**不阻断** |

### 4.1 ① 的实现方式（这是本轮的一个真实修正）

第一版我在方案里写了"魔数不认识就报①"，但实现时选了"一律交给浏览器"（更宽松）。
**结果①成了死代码**——垃圾文件报的是②。测试直接把它暴露了出来。

**修正后的语义更有用**：容器**认得出**却解不出 → ②（文件内容坏了）；容器**认不出**且解不出 → ①
（"我不知道这是什么文件"，并给出格式清单作为补救）。两者对用户是**不同的行动**，这才是真正"可区分"。

### 4.2 WAV 报错不再漏出英文

原实现把 WAV 解析器的英文原因直接拼给用户（`音频被截断或损坏：File is too small to be a WAV file`）。
现改为中文提示，原始英文原因保留在 `result.detail` 中供诊断 ✓

## 7. 调试过程中发现并修掉的问题

### 7.1 `root` 不在作用域内（会直接崩溃）

`audio-input.js` 的工厂函数没接收 `root` 参数，却在 `getContext()` 里用 `root.AudioContext`。
`detectFormat` 不碰 `root` 所以单元测试全过，**直到第一次上传非 WAV 文件才会抛 ReferenceError**。
Node 侧一调用 `getContext()` 就暴露了。已按 `decoder.js` 的既有模式把 `root` 传入工厂 ✓

### 7.2 `extract-image.html` 也解析音频，且缺 `esc()`

该页**有同样的问题**（直接调 `SSTVWav.parse`），而且**没有 `esc()` 函数**——我第一版改动引入了对
不存在函数的调用，运行时会 ReferenceError。已补上本地 `esc()` 并改走 `parseAudio` ✓

### 7.3 「无法识别」的十六进制预览是空的

`headHex` 最初是在**解码失败之后**才计算的，而那时 `buf` 已被 `decodeAudioData` detach，
`head` 视图随之变空 → 提示变成 `（前 12 字节 ）`。
**这正是我在同一段注释里写下的坑，却仍在错误路径上踩了它**。已改为在解码前快照 ✓

## 10. 遗留与建议

1. **`extract-image.html` 的隐藏载荷在转码后能否提取，本轮未验证**。公开图解出来了，但隐蔽载荷是从
   **图象域的量化块均值**读出的，比重采样敏感得多——很可能在转码后失败。本轮未声称它可用，
   建议下一轮实测（把 `tests/downloads/sstv_hidden_M1.wav` 转成 m4a 后走提取页）。
2. **`.research/` 与 `tests/audio-samples/` 是产物目录**：5 个转码样本（约 10 MB）由测试自动重建，
   可按需加入忽略名单。
3. **`js/lib/audio-input.js` 未纳入既有检查器**：`check-ui-wording.js` 的扫描集是 UI 层文件，
   新模块与其无冲突，但若将来该模块出现用户可见文案需要一并纳入。
