## 2. ★ 为什么不可兼得（报告第 3 项）

### 2.1 两个情形对搜索的需求相反

| | 预测位置精度 | 需要搜索吗 |
|---|---|---|
| **合成音频** | **精确**（偏离 200 采样、行间隔 MAD **0.0000 ms**）✓ | **不需要** ✗ 原前进式粗搜**已经正确** ✓ |
| **真实录音** | 差（偏离 **7149 采样**）✗ | **需要** ✓ 且需要**很大**的范围（±0.35 行）✗ |

### 2.2 两次失败共同的机理

**两次尝试都是"用一次全局搜索替换原来的前进式粗搜"** ✗ ——
**即使预测位置本来就对（合成情形），搜索也会返回一个"分数更高但位置不同"的候选** ✗✓

**具体地**：合成音频的同步非常干净 ✓ → **±0.4 行范围内有多个位置的匹配置信度都很高** ✗
→ **argmax 落到"邻近但错几毫秒"的位置** ✗ → **逐行错几毫秒 → 模糊 → PSNR 崩落** ✓✓

**→ 一条无条件的全局搜索**无法同时服务"预测已对"与"预测差 0.35 行"这两种情形** ✗✓

## 3. 权衡方案（报告第 4 项）—— 下一轮的具体设计

### 3.1 ★ 方案 A（推荐）：**只在"起点不在同步内"时才搜索**（严格附加式）

**关键改动**：不要用搜索**替换**原来的前进式粗搜 ✓ 而是**先判断起点条件** ✓：

```js
var startInSync = f(est.peak(samples, alignStart, syncWindow)) <= SYNC_DETECT_HZ;
if (startInSync) {
  /* 原前进式粗搜 —— 合成路径逐字不变 ✓ 不可能影响 31.23 / 30.50 */
  var cs = alignStart;
  for (; cs < alignStop; cs++) if (f(est.peak(samples, cs, syncWindow)) > SYNC_DETECT_HZ) break;
  ...
} else {
  /* 预测落在图象内容里 —— 此时才启用搜索（带置信度判据）✓ */
}
```

**为什么这样能兼得** ✓✓：
- **合成音频**：预测精确 → `startInSync = true` → **走原路径，逐字不变** ✓✓ **不可能回归** ✓
- **真实录音**：预测落在图象内容里 → `startInSync = false` → **走搜索路径** ✓ 而搜索路径已被证明能让 phigros 全部达标 ✓✓
- **两侧互斥**，不存在"一个策略服务两种情形"的冲突 ✓✓✓

**这是本次两次失败给出的直接结论**：**问题不在"用什么判据选候选"**（换判据没能解决 ✗）
**而在"是否该替换原路径"** ✗ —— **应当按起点条件二选一** ✓
