## 4. `chanOffsets` 索引约定的核对（报告第 4 项 / AC6）—— **一致，不是根因**

### 4.1 从代码与模式表核对

```
scanOrder = [G, B, R]      chanSync = 2      channels = 3

循环：for (var chan = 0; chan < channels; chan++)
      if (chan === mode.chanSync) { ...对齐同步... }
      pos = seqStart + (chanOffsets[chan] + (px+0.5)·pixelTime − centreWindowTime)·SR
```

**`chan` 不是"物理发射序号"，而是【角色序号】** ✓
**`mode.scanOrder[chan]` 才给出角色** ✓：
- `chan = 0` → `scanOrder[0]` = **G**
- `chan = 1` → `scanOrder[1]` = **B**
- `chan = 2` → `scanOrder[2]` = **R**

**而 `chanOffsets = [base+chanTime, base+2·chanTime, base]`** ✓ 按同一角色序号索引 ✓：
- `chanOffsets[0]` = `base+chanTime` → **G**（150.24 ms）
- `chanOffsets[1]` = `base+2·chanTime` → **B**（289.98 ms）
- `chanOffsets[2]` = `base` → **R**（10.50 ms）

**`chanSync = 2`** ✓ → **同步在 `chan = 2`（即 R）之前触发** ✓
→ **与布局 `[sep][G][sep][B][SYNC][porch][R]` 逐项吻合** ✓✓

### 4.2 判定

**→ 索引约定【一致】，不是根因** ✓
**（任务书怀疑"按颜色角色索引 vs 按发射顺序索引不一致"—— 核对结果显示二者在此处等价 ✓
 因为 `scanOrder` 本身就是发射顺序 [G,B,R] ✓ 而 `chanOffsets` 按同一顺序索引 ✓）**
