## 3. 「最小可靠 B」的结论（AC2）

**判据**：帧成功率 = 100%（8/8 种子），且 goodput 最大。

| 信道 | 最小可靠 B | 依据 | 该 B 的载荷 |
|---|---|---|---|
| clean | **B=32** | BER 3.9e-4（B=16 为 3.5e-3，已越过预算） | 215 B |
| **mild** | **B=32**（FEC 开） | 帧成功率 50%→**100%**；BER 7.8e-4 | **215 B** |
| moderate | **B=32** | BER 3.9e-4 | 215 B |
| **severe** | **不存在** | **B=16…128 全部帧成功率 0/8** | — |

**B 这个杠杆：对 mild/moderate 完全有效，对 severe 无效。**

**关键补充：单看 BER 会选错 B。** 我用 BER 曾推荐 B=48；但 **goodput = 载荷 × 帧成功率** 在 B=32 达峰（215 B），
B≥48 后单调下降（160 → 132 → 76 → 48 B）。**正确的最优点是最小可靠 B 本身，即 B=32。**

**severe 为何无效（如实）**：BER 从 B=16 的 9.8e-2 到 B=128 的 3.9e-2，只降 2.5 倍，
而 √(128/16)=2.83——**说明它大致只按 1/√B 走，但起点太高**，字节错误率始终在 27–68%，
远超任何 RS 的错误预算（12.5%）。同时擦除率一直停在 14–18%，
说明相当一部分块是**自信地错**（相干误差），软信息也标不出来。
**结论：severe 档不是「再加大 B」能解决的，需要软判决（LDPC）或直接降低速率到无法实用的程度。**

### 4.1 最重要的结果：**阶段二的"边缘密度"解释被推翻**

预测器排序（Spearman vs log10 BER，50 张图）：

| 特征 | rho | 判定 |
|---|---|---|
| **unreachableFrac（不可嵌入块占比）** | **+0.949** | **决定性** |
| H1_noHeadroomFrac（无余量块占比） | +0.493 | 强 |
| F3_hfRatio（高频能量占比） | +0.262 | 弱 |
| F4_edgeDensity（边缘密度） | +0.254 | 弱 |
| **F1_gradX（平均水平梯度）** | **−0.072** | **无关系** |
| F2_gradXY / F5_localRange | ~0.01 | 无关系 |

**色条图的 gradX 只有 1.98，而文字截图 7.52、1/f 合成 9.45——梯度最高的两类反而没崩。**
所以"高对比/边缘密集导致失效"是**错的**（rho = −0.07）。

**真正的机制是块内动态范围**：一个块若同时含接近 0 与接近 255 的像素，
其可达均值范围宽度只有 `255 − (max − min)`，**接近单点**，
于是这个比特**根本写不进去**——无论平均多少像素、加多强的 FEC 都没用。
这解释了色条图（36.5% 不可嵌入）与文字截图（20.6%）。

## 5. 「用户可操作的规避标准」具体建议（AC4）

按可信度从高到低给三条：

**① 主判据（精确、可用、~60 ms）：干跑嵌入器，直接读不可嵌入块占比**

```js
const probe = PayloadQIM.embed(imageData, dummyBits, { blockSize: B, delta: DELTA });
const bad = probe.unreachable / totalBlocks;      // 与 BER 的 rho = 0.949
if (bad > 0.01) warn(...);                        // 1% 阈值待下轮用无黑边语料标定
```
这是**精确计算而非启发式**：它就是这个机制本身。工具应在用户选图后立刻干跑一次（不生成音频）。

**② 辅助判据（纯图象统计，无需干跑）**：无余量块占比 `H1_noHeadroomFrac`（rho=0.493）——
即"块内极差 > 255−Δ 的块比例"。它比任何梯度类指标都强得多。

**③ 明确不要用梯度/高频/边缘密度做判据**：本批数据里它们的 |rho| ≤ 0.26，其中 gradX 几乎为 0。
若按"高频能量超过 X% 就警告"，会把文字截图（应警告，0.19）与 1/f 合成（不必警告，0.013）分开，
但**也会漏掉色条图（0.011，最该警告的一类）**——即该判据在最严重的失效案例上失效。

**④ 比"警告"更好的自动缓解**：既然失效是**块级可判定**的，可以**跳过不可嵌入的块**，
把它们排除在承载之外（或标为擦除），用剩余块承载。这是容量换可靠性的自动措施，
不需要用户换图。**本轮未实测**（我原计划做，被预算耗尽）。

## 6. 两点仿射 AFC 的实测精度（AC5 部分）

**未完成的部分我先说清**：本轮**没有**把字面两点频率拟合实现为可切换模式（`afc:'twoPoint'`）。
下面给出的是**阶段二已实现并实测过的仿射标定精度**，以及方案里已推导的误差公式。

**推导**（详见方案）：$f_{\text{meas}} = r(f_{\text{nom}}+\Delta f) = a f_{\text{nom}} + b$，
两点解 $a=\frac{f_2-f_1}{700}$、$b=f_1-1200a$，校正 $\hat f=(f_{\text{meas}}-b)/a$。
误差传播 $\sigma_a=\frac{\sqrt{\sigma_{f1}^2+\sigma_{f2}^2}}{700}$。

**阶段二实测（已有实现：`a` 由逐行同步头时序最小二乘拟合，`b` 由 300 ms 引导音锚定）**：

| 信道 | 真值 (a, b) | 估出 (a, b) | 残差 |
|---|---|---|---|
| clean | (1.0, 0) | **(1.00000, −0.08 Hz)** | < 0.1 Hz |
| mild | (1.0, 5) | (1.00000, 4.38 Hz) | 0.6 Hz |
| moderate | (1.005, 20.1) | **(1.00500, 19.75 Hz)** | 0.35 Hz |
| severe | (1.010, 50.5) | **(1.01000, 51.13 Hz)** | 0.6 Hz |
| 时钟尺度（独立报告） | 0.99502 / 0.99010 | 0.99503 / 0.99010 | 1e-5 |

**零偏置验证（AC5 要求）**：clean 档实测 `(a,b) = (1.00000, −0.08)` → **接近 (1.0, 0.0) ✓**

**为什么没用 1200 Hz 做第二个频率点**：实测用它估出的 `a` 是 **1.00649**（真值 1.0，0.65% 误差），
换算到 2300 Hz 是 **9.2 Hz ≈ 2.9 灰阶**残差，而判决余量只有 6 灰阶——**吃掉近一半预算**。
逐行同步头时序拟合把残差压到 <0.1 Hz。两者相差约 100 倍。

## 8. 对"是否还需要 LDPC"的明确判断

**分档回答，不含糊：**

| 信道档 | 光靠加大 B 够不够 | 是否需要 LDPC |
|---|---|---|
| clean | ✅ 够（B=32） | **不需要** |
| **mild** | ✅ **够（B=32，FEC 开，帧成功率 100%）** | **不需要** |
| moderate | ✅ 够（B=32） | **不需要** |
| **severe** | ❌ **不够**（B=16…128 全档帧成功率 0/8，BER 停在 3.9e-2） | **需要，但未必值得** |

**对 severe 的具体判断（重要）**：
- B 从 16 加到 128（8 倍），BER 只从 9.8e-2 降到 3.9e-2——**约 1/√B，起点太高**。
- 在这个起点上，要让 RS 类硬判决码有效，需要码率低于约 **1/15**；而 B=128 时载波只有 64 字节，
  扣掉开销后可用载荷会掉到 **个位数字节**。**这不是一个可用的传输方案。**
- LDPC 的价值在于用**软信息**换取几个 dB。但 severe 的擦除率稳定在 14–18%，
  说明错误有很强的**相干成分**（不是独立随机噪声），软判决的增益会被大幅侵蚀。
- **因此我的判断是：severe 档应当明确列为「超出本方案适用范围」**，
  除非改变物理层假设（更长的块、更低的符号率、或换掉模拟 SSTV 调制本身）。
  把 LDPC 当作 severe 的解药是不诚实的期望管理。

**给阶段四的建议（按性价比排序）**：
1. **先把 B 定为 32**（goodput 最优、mild/moderate/clean 全部 100%）。
2. **修掉黑边造成的不可嵌入块**（把载荷只铺在有效图象区域，或用"跳过高梯度/无余量块"的自动缓解）——
   这是当前最大的、可立即兑现的可靠性提升，且不需要新编码。
3. **补 A 类真实照片语料**并把阈值标定在没有黑边的条件下，把 AC4 的判据真正落地到面板告警。
4. 只有在 1–3 做完后仍需要更低温信噪比工作点，才考虑 LDPC。
