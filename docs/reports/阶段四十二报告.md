## 1. 三通道 pos 与期望值（报告第 1 项）

### 1.1 公式与常数

```
解码器 pos = seqStart + (chanOffsets[chan] + (px+0.5)·pixelTime − centreWindowTime)·SR

base(sync+porch)   = 10.500 ms
chanTime(sep+scan) = 139.740 ms
chanOffsets（scottie，按角色 G/B/R）= [base+chanTime, base+2·chanTime, base]
  G 150.240 ms · B 289.980 ms · R 10.500 ms

pixelTime（标称）= 432.0 µs = 20.74 采样 · windowFactor = 2.48
centreWindowTime = pixelTime × windowFactor / 2 = 535.7 µs
```

### 1.2 关键量

| 量 | 值 |
|---|---|
| **G 槽相对 R 槽（同一 px）** | **139.74 ms = 323.5 px** ✓ |
| 标准布局里 G 与 R 的距离 | G 在同步前 277.98 ms、R 在同步后 10.50 ms → **相距 288.48 ms** |
| `centreWindowTime` | 535.7 µs = **1.24 px** ✓ |

**→ 与 21 px 有关的量级只有 `centreWindowTime`（1.24 px）** ✗ 差一个数量级 ✗
**→ 该公式里没有 21 px 的来源** ✓

## 4. 编码器的 R 写入位置（报告第 4 项）—— **正确**

```
发射顺序（每行）：SYNC, sep, G, sep, B, SYNC, sep, R
故 R 起点 = 第二个同步起点 + syncPulse + sepPulse = 10.50 ms
标准 [sep][G][sep][B][SYNC][porch][R] 的 R 起点 = sync + porch = 10.50 ms
=> 一致 ✓（porch = sepPulse = 1.5 ms）
=> 编码器无 9 ms（21 px）量级的 R 偏移 ✓
```

**→ 编码器正确** ✓ → **不是"编解码共享的编码器错误"** ✗
**→ 错位是【解码器侧】的** ✓（而合成自往返暴露了它 ✓）
