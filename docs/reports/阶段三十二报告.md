## 3. Robot36 与我们的三通道统计（报告第 3 项）

### 3.1 三层对比

| 层 | 饱和度均值 | 亮度标准差 | R-G 相关 | G-B 相关 |
|---|---|---|---|---|
| **1 源头（音频平面）** | **32.7** | 33.4 | 0.1156 | 0.3474 |
| **2 我们的输出** | **70.9** | 59.9 | 0.3405 | 0.7864 |
| **3 Robot36 参照**（裁剪后降采样到 320×256） | **43.1** | 76.1 | 0.7368 | 0.7816 |

### 3.2 ⚠️ 这里的数字会骗人，必须解释

**我们的饱和度（70.9）反而高于 Robot36（43.1）** ✗ 这与"没色"的观感**相反** ✓

**原因**：饱和度 = `mean(max(R,G,B) − min(R,G,B))` ✓ 它对**独立噪声**极其敏感 ✗
我们的 B/R 是噪声 → 每个像素的 R、G、B 互相独立 → **每像素的 max−min 天然很大** ✗✓
→ **70.9 是"彩色噪声"，不是"彩色内容"** ✓✓

**同一逻辑也解释了 G-B 相关**：我们的 0.7864 ≈ 参照的 0.7816 ✗ **这个指标不区分好坏** ✓
（自然图像的 R/G/B 本就高度相关 ✓）

**→ 上一段和这一段合起来说明：本轮用的三个指标（饱和度、平面标准差、平面相关）
都无法区分"色度内容"与"色度噪声"** ✗ **这是本轮必须在报告里立此存照的方法论缺口** ✓

## 6. "没色"的根因（报告第 6 项）

**链条**（每一步都有本节数据支撑）：

```
解码器行时序正确（428.195 vs 428.22 ms；256 行覆盖 49.2–158.4 s）✓
       ↓
但三个色槽采到的位置"没有明确音调"：
    G 槽有强音调（prom 10–27）但值域极窄（1750–1900）
    B 槽几乎无音调（prom 2.5）
    R 槽恒在 ~1075 Hz、像素间几乎不变（prom 8–10）
       ↓
B/R 的灰度被钳到 0（<1500 Hz），只有 G 产生有效亮度
       ↓
合成图 ≈ "只有 G 通道"的灰度图 → 糊、几乎没色、只有边缘偶尔出色 ✓
       ↓
直方图佐证：单峰、偏亮（149.7）、丢暗部；参照是双峰、偏暗（90.0）✓
```

**即：不是频率映射错、不是色彩空间错、不是通道顺序错、不是整行对齐错，
而是**逐行/逐槽的采样位置整体落在没有有效图像音调的地方** ✗

### 6.1 一个可能直接解释它的异常（★ 本轮最有价值的发现）

```
录音 RMS:  从约 2 s 起全程有信号 ✓
解码器:    行 0 参考 = 49.203 s · 行 255 参考 = 158.393 s
```

**信号从 ~2 s 就开始，解码器却把第 0 行放在 49.2 s** ✗ 相差约 **47 秒 ≈ 110 行** ✗✗

若真实传输的图像从 ~2 s 开始，那么**解码器的 `imageStart` 晚了约 47 s** ✗
→ 所有槽整体落在**错误的时段**（可能落在另一段传输、或落在非图像区）✗✓
→ **这正好解释"有音调但值域极窄/无音调"的混合现象** ✓

**注意**：两种可能都存在，本轮**无法区分**：
- (a) 录音里有**多段传输**，解码器选中的是较晚的一段（那么 49.2 s 是对的）✓
- (b) `imageStart` **确实晚了 47 s** ✗

**判据（下一轮第一步）**：把解码器的 `imageStart` 与**独立检测器**（阶段二十六）测出的
**首个同步脉冲序列的起点**对比 —— 若录音只有一段传输，两者必须一致 ✓
