## 2. 任务 1 的方案选择与理由（报告第 2 项）

### 2.1 先判断面板用途（这是选择依据）

`renderExtensions()` 渲染的是**扩展点自检面板**，由三块组成：

| 内容 | 性质 |
|---|---|
| 「扩展点 / 已注册 / 当前生效」表 | 从**活的** `Channel` 注册表读出（嵌入器 / FEC / 干扰模型） |
| 「各模式可嵌入容量估算」表 | 按模式结构**解析推算**的容量 |
| L314 那句 | **给下方容量表做限定说明** |

**结论：它是"扩展接口的演示/自检面板"，受众是改代码的人**——但原句后半段（"阶段一未实现任何嵌入"）
现在是假的。

### 2.2 选 **方案 A + 一个指针**（经你确认）

| 方案 | 判断 |
|---|---|
| **纯 B**（改为"图片隐藏已实现，请访问 embed-image.html"） | ❌ **会删掉对容量表的限定**。那张表的数字是解析推算、不是实测，这句话是它唯一的解释；删掉后读者会把估算当实测值，**比原来的假陈述更糟** |
| **纯 A**（只陈述现状） | 能修掉假陈述，但读者仍不知道图片隐藏到底做了没有 |
| **A + 指针** ✅ | 既保留限定、又告知已实现的功能入口 |

### 2.3 最终文案（`js/app.js:314–316`）

```js
rows.push('<p class="hint">按模式结构解析得出的<b>解析估算</b>，不是已实现的隐写信道测量值。' +
  '默认生效的 <code>identity</code> 嵌入器为直通（容量 0），下表为各模式在相应方案下的<b>上限估算</b>；' +
  '已实现的图片隐藏见 <a href="embed-image.html">图片隐藏 · 嵌入端</a>。</p>');
```

**三点改进**：① 假陈述消失；② 保留并**强化**了"解析估算 ≠ 实测"的限定（并说明了下表数字的准确含义：
各方案下的**上限估算**）；③ 给出已实现功能的入口。
