## 1. has_sync 探测的脉冲统计（报告第 1 项）

`tests/diagnose-sync-tracking.js`，两个音频用**同一检测器**跑，互为基准。

### 1.1 ⚠️ 你建议的 1.5 ms 窗**不可用**，自诊断给出了原因

第一版照你的规格实现（Hann **1.5 ms** @1200 Hz、跳 0.25 ms）。**对照组检出 0 个脉冲** ✗
脚本的自诊断输出：

```
!! 零脉冲，自诊断: 最大 E1200 = 8.948e+0 · 最大比值 E1200/max(其他) = 1.248 · 比值 > 1.4 的 bin 数 = 0
=> 1200 Hz 从来不是局部最强音: 阈值 k=1.4 太严，或基频/采样率口径有误
```

**根因**：1.5 ms 窗的频率分辨率约 **667 Hz**，而同步音 1200 Hz 与图象带下沿 1500 Hz **只差 300 Hz**
（0.45 个分辨单元）→ **根本分不开** ✗ 要分开 300 Hz 至少需 **3.3 ms** 窗，实用上 ≥ **8 ms**
—— 而同步脉冲本身就只有 9 ms，所以**窗长必须接近脉冲长度**才能兼顾选择性与时长 ✓

**改为**：正交解调 + 2 ms 一阶包络（**这是阶段二十五已验证在对照组给出 256 脉冲、MAD 0.000 ms 的那个检测器**），
只把**时间抽取从 1 ms 收紧到 0.25 ms** ✓ 即**改用已验证的方案 + 提高时间分辨率**，
而不是换一个频率上不成立的窗 ✗

## 2. 拟合结果（报告第 2 项）

模型 `位置 = skip + rate × 行号`，用 **最小二乘 + RANSAC 外点剔除**（理由见本轮方案：

| 量 | 对照组 | **phigros** |

| skip | — | — |

### 2.1 判定：**没有漂移**

- **每行漂移 −1.597 采样（−0.0078%）**，256 行累计 **−0.02 行** ✓ **可忽略**

- → 你方案里的判定分支：**"rate ≈ 0 → 没有漂移，问题在别处"** ✓

### 2.2 ⚠️ 由此**推翻我阶段二十四/二十五的结论**

阶段二十五我写过"phigros 的同步脉冲**不落在单一栅格上**、**时钟不相干**（inlier 仅 61%，

**原因**：那次用的栅格周期是 **428.000 ms**（来自 1 ms 量化的旧检测器），而真值是 428.079–428.22 ms；
0.08–0.22 ms/行的周期误差在 256 行上累积 **20–56 ms（≈1 万个采样）**，足以让半数脉冲"偏出 ±2 ms 栅格" ✗

你方案的任务 3 是"用 `(skip, rate)` 重新计算每行起点并重解"。**实测表明没有可校正的漂移**

## 4. 根本原因：解码器的行斜率估计偏差 −2.148%（报告第 5 项）

### 4.1 定量对照

| 量 | 真值（本轮实测） | 解码器自报 | 差 |
|---|---|---|---|
| 行周期 | **20552.963 采样**（428.1867 ms） | **20113.0 采样**（由 `clockScale = 0.97852` × 标称 20554.56 反推） | **−441.5 采样/行 = −2.148%** ✗ |
| 标称 | 20554.56 | — | — |

### 4.2 因果链（每一环都有实测支撑）

```
真实行周期 ≈ 标称（-0.008%）
       ↓
但解码器把行周期拟合为 20113（-2.148%）       ← 缺陷在此
       ↓
逐行推进时每行落后 441.6 采样
       ↓
441.6 × 23 行 ≈ 10277 采样 = 半个行周期       ← 锁失窗口
       ↓
约 23 行后 alignSync 的预测位置偏出真同步，搜索不到 → 采到错误位置
       ↓
输出：前二十来行结构尚可，其后全为噪声
```

**"前二十来行尚可"与本轮算出的 23 行锁失窗口吻合** ✓ 也与你最初报告里
**"几乎纯噪声，顶部有横向结构"** 完全一致 ✓✓

### 4.3 拟合偏差的机制（实测证据）

| 证据 | 数值 |
|---|---|
| 间隔 **均值** | **399.9967 ms** |
| 间隔 **中位** | **428.0790 ms** |
| **差值** | **−28.08 ms** ✗ |
| 间隔标准差 | 129.93 ms |

→ 音乐产生的**短间隔离群点**把**均值**（以及**最小二乘**斜率）整体拉低 ✗
标定用的是**最小二乘回归**，对离群点**不稳健** ✓
**这正是阶段二十早就观察到、但当时未串起来的那条线索**：
"脉冲间隔的均值 377.211 ms 明显低于中位 428.000 ms" ✗

### 4.4 修复方向（下一轮，**未在本轮实施**）

| # | 修法 | 位置 |
|---|---|---|
| **1（推荐）** | 把行斜率的**最小二乘**换成**稳健估计**：对相邻间隔取**中位数**、或 **Theil–Sen / RANSAC** | `js/lib/sstv-decode.js` 的标定段（`clockScale = slope / nominalLineSamples` 附近，约 L652） |
| 2 | 在拟合前**剔除离群间隔**（如中位 ±10% 之外） | 同上 |
| 3 | 保留现有跟踪逻辑不动 | `alignSync` + `measuredLineSamples` 的逐行搜索**本身是正确的**（对照组跟踪误差 0.58 像素）✓ |

**预期**：斜率从 20113 回到 ≈20553 后，逐行预测不再流失，
`alignSync` 可持续锁住真同步 → phigros 应能解出可辨认内容 ✓
**验证**：`node tests/real-s1.test.js`（行间相关应从 0.1962 显著上升）+ `roundtrip.js`（M1/S1/PD 不回归）✓

**为什么本轮不动手**：按你确认的规则"先诊断、验证有效才集成"；而且**本轮的诊断结果把修复目标
从"跟踪"改成了"标定的稳健性"**，这是一个**与计划不同的改动**，值得单独一轮、
并且必须在改前就把回归门禁准备好 ✓
