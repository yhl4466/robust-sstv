### 3.2 AFC / 时钟恢复的实测贡献（AC3）

| 配置 | 成功 | 平均 σ_HF | 平均 PSNR | 相对 raw |
|---|---|---|---|---|
| AFC off + 时钟 off（阶段一行为） | 23/26 | 19.57 | **21.12 dB** | – |
| 仅常数频偏 | 23/26 | 19.58 | 21.12 dB | 0.00 |
| 字面两点频率拟合 | 23/26 | 19.78 | 21.03 dB | **−0.09** |
| 两点 + 时钟 | 23/26 | 19.80 | 21.03 dB | −0.09 |
| affine，无时钟 | 23/26 | 19.59 | 21.12 dB | 0.00 |
| **affine + 时钟（默认）** | 23/26 | 19.60 | **21.11 dB** | **−0.01** |

**结论（不含糊）：在这 26 段材料上，AFC 与时钟恢复对 PSNR 的净贡献是 −0.01 dB，即"没有贡献"；字面两点拟合反而稳定地差 0.09 dB。**

**为什么会这样——交叉点搜索给出了定量解释**（对干净真实录音施加递增时钟误差）：

| 时钟误差 | 真值 a | raw PSNR | affine+时钟 | **增益** | 估出的 a |
|---|---|---|---|---|---|
| 0 ppm | 1.00000 | 26.71 | 26.71 | 0.00 | 1.00000 ✓ |
| 200 ppm | 1.00020 | 26.81 | 26.77 | **−0.04** | 1.00020 ✓ |
| **1000 ppm** | 1.00100 | 25.68 | **26.23** | **+0.55** | 1.00100 ✓ |
| 5000 ppm | 1.00500 | 18.76 | **20.18** | **+1.42** | 1.00500 ✓ |
| 10000 ppm | 1.01000 | 16.18 | **17.43** | **+1.25** | 1.01000 ✓ |
| 20000 ppm | 1.02000 | 10.41 | 10.99 | +0.58 | 1.09390 ✗ |
| 50000 ppm | 1.05000 | FAIL | FAIL | – | – |

- **交叉点在 0.02%–0.1% 之间**：低于此，时钟恢复无收益甚至微负；高于此开始回本，0.5% 时峰值 +1.42 dB。
- **估计器精度极好**：0.02%/0.1%/0.5%/1% 全部**精确估出**（1.00020 / 1.00100 / 1.00500 / 1.01000）；**2% 时崩溃**（1.09390，超出同步拟合 ±10% 有效窗）。
- **物理解释**：200 ppm × 114 s ≈ **0.05 行**的累计滑移，而像素窗宽约 2.4 ms（≈0.5 行）。**SSTV 的像素窗本身就容忍真实录音机的时钟误差。** 所以 AFC/时钟是针对这批材料**不存在的失效模式**的保险——不是无用的代码，但目前不产生收益。

## 4. 失败案例根因（AC4）

**3 例失败，全部停在 `findHeader`，且 6 种配置一致失败。**

**单因子消融**（把每个损伤单独施加到干净真实录音上）：

| 单独施加 | 结果 | PSNR |
|---|---|---|
| 什么都不加 | OK | 26.71 dB |
| SSB 300–2700 带通 | OK | 14.20 dB |
| 50 Hz 工频 −20 dB | OK | 25.33 dB |
| 2700 Hz 邻道 −14 dB | OK | 20.83 dB |
| 只做 2700 Hz 低通 | OK | 26.28 dB |
| 带倾斜 −8/−14 dB | OK | 26.09 dB |
| 房间 RT60 0.4 s | OK | 15.08 dB |
| **带倾斜 + 房间** | **FAIL (findHeader)** | – |
| **SSB + 工频** | **FAIL (findHeader)** | – |
| **SSB + 邻道** | **FAIL (findHeader)** | – |

**根因不是任何单一损伤，而是两种损伤的叠加把 `findHeader` 的判决裕度耗尽。**

- `findHeader` 是一个**固定阈值**的标定头检测器；每种单独损伤都只把匹配得分压低一点，仍然过阈；两种同时出现就掉到阈值以下。
- 这解释了一个反直觉现象：**`ssb-agc`、`ssb-qsb-slow`、`ssb-qsb-deep` 带同样的 SSB 滤波却解码正常**——因为它们的第二个损伤（AGC / 衰落）是**乘性增益**，不改变频谱形状；而工频与邻道增加的是**带外能量**，直接抬高了检测器的噪声底。
- 注意失败与"信噪比低"并不等价：`combo-hard` 的带内 SNR 只有 2.8 dB 却**解码成功**（虽然质量很差 6.57 dB）。**失败与否取决于标定头检测裕度，而不是总体 SNR。**

**改进方向（明确、可执行）**：
1. **把 `findHeader` 的固定阈值改成自适应**：用局部噪声底归一化匹配得分（即用匹配滤波器的输出 SNR 而非绝对值判阈），或对多个阈值做扫描并选第一个能自洽解出 VIS 的起点。
2. **在标定头检测失败时退化到"同步音搜索"**：不依赖 300 ms 引导音，直接用逐行同步音（1200 Hz）的周期性做周期图检测后回推起点。
3. **对抗带外能量**：在标定头检测前加一级自适应的窄带化/白化（例如对 1150–2350 Hz 之外的能量做抑制），这对"工频/邻道"这类真实干扰直接对症。

### 5.2 一个必须点明的方法论问题

σ_HF 在滤波后大幅下降（干净图 10.87 → 7.00），**但 PSNR 同时下降**。
**⇒ σ_HF 会被"模糊"直接压低，因此它不能单独用来断定"图变好了"。** 它是噪声指示器，不是质量判据。产品里的 `suggest()` 只把它当作**筛选启发式**，并且**默认不自动施加滤波**。

## 7. 其他值得记录的实测事实

1. **削波鲁棒性很好（真实且符合物理）**：1.5× 与 3× 硬削波的结果与干净**完全相同**（26.71 dB、σ_HF 10.87）。原因是 SSTV 是调频类信号，**信息在瞬时频率里，而硬削波保留过零点**（FM 限幅效应）。到 8× 才开始劣化（21.63 dB）。
2. **采样率鲁棒性很好**：8k / 11.025k / 16k / 22.05k / 44.1k 全部解码，25.83–26.71 dB。**解码器与采样率无关**，这对真实场景很关键。11.025 kHz 略差（25.83 dB）。
3. **`findHeader` 能跨过前导静音**：3 s 静音后仍成功 ✓。
4. **尾部截断 8% 仍可解**（16.62 dB，带截断告警）✓。
5. **主流退化不是 AWGN 而是 SSB 通带**：单独 SSB 滤波就把 PSNR 从 26.71 打到 **14.20 dB**（−12.5 dB），比 12 dB AWGN（−8.2 dB）更严重，而削波几乎无损。**这决定了下一步该优化什么**（见 §8）。
6. **`real-colaclanth-8k` 明显更脏**（σ_HF 21.77 vs 10.87，无参考图）。两段真实录音的质量差异说明**单段录音不足以代表真实分布**。

## 8. 对"下一步该做什么"的建议

按**实测收益**排序，而不是按技术时髦度：

1. **修 `findHeader` 的固定阈值（最高优先）**。它是本批材料里**唯一的失败阶段**（3/3 失败都在这里），而根因是"双损伤叠加耗尽裕度"。改成自适应阈值 + 同步音退化搜索，预期能把 3 例失败救回 2 例以上。**成本低、收益直接。**
2. **针对 SSB 通带做频率响应/群延迟校正**。它是**最大的单一质量杀手**（−12.5 dB），远超 AWGN。方向：在解调前估计信道频响（用已知的 1200/1500/2300 Hz 参考电平与同步音）并做反向均衡；或改用对群延迟不敏感的频率估计（如过零率 + 相位差分混合）。
3. **后处理保持"默认关 + 建议开"**，并在 UI 里同时显示 σ_HF 与 lag1（因为 σ_HF 可被模糊压低）。**不要**把后处理做成默认开启。
4. **AFC/时钟维持现状**，但**在报告与文档里如实标注"在真实录音上暂无收益"**，避免后续误以为它在起作用。若将来要支持录音机时钟严重失配的素材（>0.1%），它会在那里回本。**顺手把 `two-point` 模式默认关闭**（它稳定地差 0.09 dB）。
5. **补真实样本**（若要继续）：archive.org/wikimedia 不可达时，GitHub 是最可行的渠道——建议定向寻找**带真实录音 fixture 的 SSTV 解码器仓库**（本次从 2 个仓库就找到 1 段）。
6. **PD120/PD180 仍然是最大的能力缺口**（见 §9）。
