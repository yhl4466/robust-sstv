### 8.1 全量连续运行的一次失败（如实记录）

**对这次失败的判定**：同一份 `browser-e2e.js` 在**单独运行下两次通过**（改名后立即一次、发现失败后又一次），因此这不是改名或本轮改动造成的确定性回归，而是该套件在长时间连续运行下的**负载敏感性**——阶段六已记录过完全相同的现象（当时由并行的 B=32 矩阵作业占满 CPU 触发，空闲机上全通过）。

**本轮为此做的改进**：`list-tests.js` 原先只保存每个套件的最后一行判决，失败后无法从清单看出失败在哪 3 项。现已改为同时捕获并记录所有 `FAIL` 行（写入 `test-manifest.json` 的 `failures` 字段）。**当前这份清单是改进之前生成的，因此没有失败明细**；重新运行 `node scripts/list-tests.js` 即可得到带明细的清单。

### 9.2 项目层面的已知限制（论文表 9 的 L1–L8）

| 编号 | 限制 | 实测依据 |
|---|---|---|
| L1 | **标定头检测在两重损伤叠加时失败** | 3 段样本全部终止于 findHeader；阈值放宽 3.5 倍仍无候选（假说已证伪） |
| L2 | **PD 族缺真实录音验证** | 检索 6 个公开仓库仅得 M1 样本；规格文档不可获取，故 PD 正确性仅自洽往返支撑 |
| L3 | 边带载荷容量仅数百字节 | B=32 时载荷 215 B，扣图片头后 200 B |
| L4 | 交织深度受码字数限制 | B=32 时载波仅容一个 255 字节码字，端到端深度 1–2 |
| L5 | 严重档超出适用范围 | B 自 16 扫至 128，帧成功率恒为 0 |
| L6 | AFC/时钟在真实录音上无净收益 | 26 段平均 −0.01 dB；交叉点 0.02%–0.1% |
| L7 | σ_HF 可被模糊压低 | 干净样本滤波后 σ_HF 10.87→7.00，同期 PSNR 下降 |
| L8 | PD 解码耗时较高 | PD120 约 46 s，M1 约 7 s |

### 9.3 两处技术债

**其一：`browser-e2e.js` 的负载敏感性。** 该套件在长时间连续运行下会失败（本轮全量运行 3 项，阶段六同因），单独运行稳定通过。根因未定位到具体机制，只知道与机器负载相关。建议后续为该套件单独加超时与重试策略，或把其中对时序敏感的上传与下载断言改为轮询等待。

**其二：`browser-e2e.js` 依赖中间产物。** 其新增的 PD120 期望依赖 `tests/out/enc_PD120.wav`，该文件由 `roundtrip.js` 的编码阶段写出。若单独运行 `browser-e2e.js` 而不先跑 `roundtrip.js`，该断言会因文件缺失而失败。`list-tests.js` 的内部顺序（`roundtrip.js` 先于 `browser-e2e.js`）掩盖了该依赖，应改为在套件内自行生成所需音频。
