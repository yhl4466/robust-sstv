## 1. 采用的方法与理由（报告第 1 项）

**按你的推荐先实现方法 B（Theil–Sen）**：无需调参、容忍约 29% 的污染对，N≈256 时开销可接受。

**但加了一处工程约束**：`noteSync` **每次同步都重算**（256 次），若每次对全部 N 个观测做 O(N²)
Theil–Sen（32k 对 + 排序），一帧约 **1.2 亿次比较** ✗ → 改用**最近 64 个观测的滑动窗口**
（2016 对/次 × 256 次 = **52 万**，快约 200 倍），且对缓慢漂移更敏感 ✓

**结果：方法 B 更差**（19127，相关 0.0676）✗ 随即按你的阶梯退到**方法 A**（相邻间隔中位数）：
**同样更差**（19395，相关 0.1041）✗

**方法 B 为什么更差（有明确机理）**：Theil–Sen 的分母是**观测数组的索引差** `b − a`，
它等于**行差**的前提是"每行恰好一个观测" ✗ 序列一旦缺行，索引差小于行差 → **斜率被系统性低估** ✓✓
这正好解释 19127 **低于**最小二乘的 20113（低估得更狠）✗
方法 A 不受缺行影响，但它仍然只给出 19395 —— 说明**序列本身的中位间隔就不对** ✓
