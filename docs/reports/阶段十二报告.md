## 3. 是否有遗漏的引用（报告第 3 项）

### 3.1 结论：没有遗漏

我做了三层验证，而不是只靠一次搜索：

**第一层——全项目搜索 `阶段.*报告.md`（AC2 的字面要求）**：19 处命中，逐处核对全部正确：
- `README.md` 12 处 → 全部带 `docs/reports/` 前缀 ✓
- `docs/reports/阶段四报告.md` 1 处 → 同目录兄弟链接 `阶段三报告.md` ✓ 可解析
- `docs/reports/阶段八报告.md` 1 处 → 描述改名的**文件名反引号**，已加注位置 ✓
- `scripts/move-reports.js` 5 处 → 迁移工具自身的规则数据与文件名判断 ✓

**根目录已 0 份报告**，因此不存在"还指向根目录"的引用。

**第二层——新的永久性链接完整性检查**：`scripts/move-reports.js` 现在每次运行都会校验
**README.md 与 `docs/reports/` 下每个 .md 的每一个相对链接是否真的能解析**。这条检查会长期有效，
而不是一次性的人工核对。

**第三层——迁移器自带的后置验证**：报告仍在根目录的数量、`docs/reports/` 内的数量、
以及"仍以根为基准的相对链接数"（含 `/` 且不以 `../` 开头的判为失效）。

### 3.2 验证器自身的两个问题（我修掉了）

1. **误报兄弟链接**：第一版把 `阶段三报告.md`（无斜杠、同目录）判为"根相对失效链接"。
   正确规则是：**含 `/` 且不以 `../` 开头的才是根相对**。已修正。
2. **`阶段十二报告.md` 一度显示为断链**：因为链接检查先于本报告创建而运行。这恰好**证明检查有效**——
   它准确抓出了一个真实存在的悬空链接。

### 3.3 链接检查的实测结果（含对一处推测的更正）

**实测：38 个相对链接 / 13 个文件 / 0 断链。**

我在起草本节时曾推测 `阶段五报告.md` 与 `阶段六报告.md` 里的 8 个 `scripts/out/*.png` 图片链接会
报断链——**实测推翻了这个推测**：这些图片在本检出中真实存在，因为前几轮已运行过
`eval-postprocess.js` 与浏览器套件。检查结果为准，推测作废。

不过这 8 个链接确实指向**可再生产物**（`scripts/out/` 是产物目录）：在一个全新的克隆中它们不会存在，
届时链接完整性检查会如实报出 8 处断链。两种处理方式：

| 方案 | 说明 |
|---|---|
| **A（推荐）** | 让检查把 `scripts/out/` 下的目标视为可再生产物，缺失时记为提示而非失败 |
| B | 在文档中注明这些图片需先运行对应脚本 |

当前无需处理：本检出的检查是干净的。
