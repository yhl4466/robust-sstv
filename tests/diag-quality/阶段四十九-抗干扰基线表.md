## 判读

1. **AWGN 是最强的一维**。SNR 30.43 (30 dB) / 29.40 (20) / 27.76 (15) / 25.07 (10) / 22.06 (6)。
   按干净 30.50 折算，噪声要把 PSNR 压到 25 dB 以下需要 SNR 低于 10 dB。
2. **削波几乎无影响**。8×（门限压到峰值的 1/8）仍有 29.50 dB、抖动 5 采样。
3. **采样率失配平滑但代价大**。27.14 (0.1%) / 23.94 (0.2%) / 19.72 (0.5%) / 17.26 (1%) / 失败 (2%)。
   抖动全程仅 4–5 采样、钟差被准确测出（0.2% 报 −0.200%，1% 报 −0.990%），
   且 PSNR 损失沿扫描方向**均匀**（左 14.9 / 右 13.5）—— 丢分不在同步锁定，也不在行内累积。
4. **声学路径是最差的实用维度**。RT60 0.20 s 只剩 23.39，0.30 s 17.79，0.60 s 直接失败。
   诊断（`tests/diagnose-reverb.js`）表明：行锁 MAD 仅 7–12 采样（不足 1 像素），
   而 1.3 ms 窗内的主频估计标准差达 **230 Hz** —— 丢分来自多径填满了像素级分析窗，不是同步。
5. **频率偏移存在危害性不对称**。正偏 30.40 / 30.87 / 30.80 / 31.54（+5/+10/+20/+50 Hz，**无损失**），
   负偏 27.18 / 21.92 / 17.32（−10/−20/−50 Hz，**严重损失**）。
   AFC 在两侧都准确估计出偏移（b = +49.74 / −49.91），所以不是标定问题，是真实缺陷。
   三个候选机理已被测量逐一**排除**：
     · `SYNC_DETECT_HZ` 原始阈值 —— 读数正确跟随平移，两侧 0% 越阈（diagnose-sync-threshold.js）
     · alignSync 两侧分支不同 —— 分支计数完全相同（diagnose-asymmetry-branches.js）
     · 标定斜率 a 的短窗偏置 —— 短窗偏置仅 0.01 Hz（diagnose-header-slope-bias.js）
   频移实现本身已与 FFT 参考对拍验证，且该参考先自校验再使用
   （`tests/verify-freqshift.js`：参考在纯音上频率误差 < 0.35 Hz、幅度比 1.0000）。
6. **`SYNC_DETECT_HZ` 与图像带余量原为量纲错误**（阶段四十九修正）。两者都定义在名义轴上
   却被用在原始频率上。门限的实际后果：不做映射时，+100 Hz 频偏只剩 50 Hz 名义余量，
   +150 Hz 时余量为 0。修正后余量恒为 150 Hz。带余量的误差仅为 (1/a−1)×200 Hz——1% 时钟
   误差下约 2 Hz。**这是正确性修正，不是质量修正**，上表中各格在修正前后变化均在噪声内。

## 测量工具的可信度

本表的数字来自 `tests/degradation-matrix.js`，其退化模型由 `tests/model-selftest.js` 验证
（频移、混响、削波三项，全部通过）。这不是形式主义 —— 建立本表的过程中，**四个模型 bug**
先后产生过看似合理的错误数字：

| bug | 若不修会得到的结论 |
|---|---|
| 频偏用重采样模拟（而非频谱平移） | 把时钟误差当成调谐误差，5 Hz 看起来值 8 dB |
| 混响用反馈梳状滤波器 | 连 RT60 0.15 s 都失败 —— 测的是模型而非接收机 |
| 希尔伯特 FIR 的 I/Q 错位一个群延迟 | 与 FFT 参考只有 −3 dB 波形一致，但音调测频仍正确，故多轮检查都没发现 |
| 削波在峰值 0.5 下是无操作 | 「8× 削波完全无影响」—— 其实根本没施加 |

**测量侧**同样有教训，且代价更大：阶段四十九为追踪「真实录音是否存在分段频偏」写了三个
诊断脚本，得到 +100..150 / +226..395 / +65 Hz 三个互相矛盾的答案。事后用
`tests/diagnose-measurement-validation.js` 对合成已知信号校验，才定位到原因：**三种方法都被
150 Hz 外的强邻音拉偏**，偏置分别为 −51.5 / 读到邻音 / −14.0 Hz —— 与它们声称的效应同量级。

结构性的原因：1200 Hz 同步音后面紧跟 porch 与扫描，所以任何长到能分辨同步的窗都同时含有
图像内容，而**纯音对照无法暴露这一点**。因此本表中任何涉及真实录音频偏的说法都不成立，
相关三个脚本已在文件头标注 RESULT INVALIDATED。

### 声学路径：为什么它不是一个"实现均衡器"的任务

三条独立测量（`tests/diagnose-channel-estimation.js`、`tests/diagnose-pixel-estimator.js`）指向同一结论：
这个缺口不能靠反卷积或更好的估计器关闭。

1. **用真实 IR 反卷积的收益上界是 +0.08 dB**（17.73 → 17.81，RT60 0.30 s）。已知信道、
   256 抽头 Tikhonov 反卷积，没有任何改善。所以问题不在"估不准信道"，而在信息已被破坏。
2. **从信号自身结构估计信道不可行**：以 257 个同步脉冲对齐取平均得到的信道估计，与真实 IR
   在 9–50 ms 尾部的吻合度只有 **−4.0 dB**（即基本是噪声）。原因有二 —— 同步音只有 9 ms，
   其自相关不足以激励出长尾；且混响用的是扩散（全通）尾巴，幅度响应平坦而相位响应剧烈，
   本质上不是一个可以被稳定求逆的滤波器。
3. **像素估计器的方差在混响下几乎不变**（平坦图中位真值 127：σ 从 7.40 级只升到 8.18 级，
   即 23 → 26 Hz）。PSNR 的崩塌来自**极端离群值**：极值从 134 恶化到 224/254，MAD 从 0 升到 14。
   也就是说受损的不是典型像素的精度，而是少数像素被完全捕获。这解释了为什么"换一个更稳的
   估计器"这个方向的收益有限 —— 方差本来就没有变差。

因此声学路径若要真正改善，需要的是**在解调之前**恢复波形（多麦克风/去混响前端、或利用帧间
冗余的迭代译码），而不是在现有估计器上做文章。这是一个独立的工作包，不应在缺少上述证据时
贸然开工。
